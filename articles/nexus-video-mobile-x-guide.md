# uni-app x 视频编辑前端：把时间线、本地演示和导出能力分开验收

评估视频编辑项目时，建议先把需求拆成三部分：用户怎样编辑、任务怎样处理，以及最终文件怎样生成。编辑界面能正常操作，只回答了第一部分；另外两部分需要单独验证。

`nexus-video-mobile-x` 是面向 uni-app x 的前端组件与示例，公开说明涉及素材与作品管理、时间线，以及 AI 生成流程的本地演示。它适合作为前端接入评估的起点。[插件说明](https://ext.dcloud.net.cn/plugin?id=30632)

## 1. 先明确这次交付要验收什么

启动项目时，可以先列出三项最小目标：

- 编辑目标：用户能否按预期完成素材选择和时间线操作。
- 任务目标：用户能否看懂等待、完成、失败等状态。
- 文件目标：导出的文件能否在指定设备或播放器中打开。

这三项最好分别记录结果。尤其在产品演示中，页面里的完成提示、预览画面和实际下载文件应分别检查，避免把一种结果当成另一种结果。

## 2. 先看清已有的导出边界

已核对的公开说明中，Web 本地导出范围为最高 720p、WebM、最长两分钟；原生端没有视频编码器。验证记录区分了 Web 编译与录制、Android 编译，不能据此推定 Android 已能生成视频文件。[导出与平台说明](https://ext.dcloud.net.cn/plugin?id=30632)

因此，建议把目标格式、分辨率、时长和播放环境写进需求单，再逐项判断现有能力是否匹配。如果业务要求不同的文件规格，应把相应处理链路单独列入评估，而不是等界面完成后再补充。

## 3. AI 流程先确认输入、状态和结果

这里的 AI 生成属于本地流程演示，真实服务、后台与存储仍需要项目集成。[当前功能说明](https://ext.dcloud.net.cn/plugin?id=30632)

接入真实服务时，建议先定义清楚：

1. 提交什么输入，以及哪些输入不允许提交。
2. 如何区分排队、处理中、成功和失败。
3. 用户取消或重复点击时，界面应该怎样处理。
4. 结果通过什么方式返回，失效后怎样提示。
5. 哪些错误可以重试，哪些需要用户修改输入。

这份约定可以先用文字完成，再映射到后台接口和页面状态。具体服务商、费用、素材授权与数据处理方式，也应由项目单独确认。

## 4. 用短样本完成第一轮验证

建议先准备一组有使用权限、内容简单的测试素材，完成一条尽量短的流程：进入编辑页、操作时间线、预览、导出、重新打开产物。

每轮测试至少记录：

- 浏览器或设备环境。
- 输入素材的格式和时长。
- 本次编辑操作。
- 目标输出规格。
- 实际文件是否生成，以及播放检查结果。

验收导出时，应检查产物本身，不只检查进度条。画面顺序、时长和播放结果都应该对应本次编辑。如果业务需要声音，还应把声音作为单独的验收项。

## 5. 再决定后续集成范围

完成最小流程后，可以把剩余需求分成三组：页面调整、服务端集成、视频处理能力。这样的拆分方便估算工作，也方便确认某个问题应该在哪一层解决。

如果你需要 uni-app x 视频编辑界面的起点，可以先查看 [nexus-video-mobile-x 的公开说明与示例范围](https://ext.dcloud.net.cn/plugin?id=30632)，再用自己的目标平台和输出规格做验证。把现有能力与待集成部分写清楚，后续开发和交付都会更容易核对。
